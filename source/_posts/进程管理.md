## 进程与线程

### 1\. 线程和进程的区别是什么？

核心区别是：**进程是资源分配和隔离的基本单位，线程是 CPU 调度和执行的基本单位**。

-   进程通常拥有独立的虚拟地址空间、文件描述符表和权限信息等资源；同一进程内的线程共享这些资源。
-   每个线程都有自己的程序计数器、寄存器、栈和线程局部存储，以保存独立的执行状态。
-   进程之间默认相互隔离，通信需要借助 IPC；线程共享进程内存，通信更直接，但必须处理并发同步问题。
-   创建和切换进程通常比同一进程内的线程开销大。
-   一个线程发生普通错误，通常会导致其所在进程退出，进而影响该进程内的其他线程；一个普通进程崩溃通常不会直接破坏其他进程。

### 2\. 进程、线程、协程的区别是什么？

三者主要区别在于**资源隔离、调度主体和切换成本**：

| 对比项 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 资源关系 | 拥有独立地址空间和系统资源 | 共享所属进程的大部分资源 | 通常共享所属线程的资源 |
| 调度者 | 操作系统内核 | 操作系统内核 | 通常由语言运行时或用户态调度器调度 |
| 独立状态 | 地址空间、进程上下文等 | 寄存器、栈、线程局部存储等 | 协程栈、程序位置等 |
| 切换开销 | 通常较大 | 通常小于进程 | 通常最小，可在用户态完成 |
| 隔离性 | 强 | 较弱 | 更弱 |

协程适合大量 I/O 密集型任务，但协程本身不等于并行。如果多个协程只运行在一个内核线程上，它们无法同时使用多个 CPU 核心；而且一次阻塞式系统调用还可能阻塞整个线程，除非运行时使用异步 I/O 或把任务调度到其他线程。

### 3\. 为什么进程崩溃通常不会对其他进程产生很大影响？

因为操作系统通过虚拟内存、权限控制以及用户态与内核态**实现了进程隔离**，为每个进程提供独立的地址空间。一个进程崩溃时，通常只会破坏自己的内存和执行状态，操作系统随后会终止该进程并回收资源，因此不会直接影响其他进程。不过，如果它是关键服务、与其他进程共享数据，或者崩溃发生在内核态，仍可能间接影响其他进程甚至整个系统。

### 4\. 进程是分配资源的基本单位，这里的资源指什么？

进程是资源分配的基本单位，这里的资源主要包括独立的虚拟地址空间、打开的文件和 Socket、I/O 设备、权限信息以及进程间通信资源等。同一进程中的多个线程通常共享这些资源，但每个线程拥有自己的栈、寄存器和程序计数器。CPU 实际调度的基本单位通常是线程。

### 5\. 为什么进程之下还要设计线程？

主要是为了在保留进程资源边界的同时，提供一种**更轻量的并发执行方式**。

进程主要解决资源分配和隔离问题，但进程的创建、切换和通信成本比较高。为了在共享同一份资源的前提下实现更轻量的并发，操作系统引入了线程。线程共享进程的地址空间、文件等资源，但拥有独立的栈、寄存器和程序计数器，因此可以独立执行，并充分利用多核 CPU。

### 6\. 多线程相比单线程有哪些优势和劣势？

多线程的主要优势是提升**并发能力和响应性**：I/O 密集型任务可以在部分线程等待时运行其他任务；CPU 密集型任务在可并行拆分且有多核资源时，也可能缩短总耗时。此外，线程间共享数据比进程间通信更直接。

它的劣势是程序复杂度和运行开销都会增加，包括线程创建与切换、栈内存占用、锁竞争和缓存一致性开销。共享数据还可能产生竞态条件、死锁、活锁和可见性问题，使测试与排查更困难。

### 7\. 多线程是不是越多越好？线程太多会有什么问题？

多线程不是越多越好。线程过多会增加上下文切换、内存占用和操作系统调度开销，同时加剧锁竞争，降低 CPU 缓存命中率，还可能引发死锁和资源耗尽。CPU 密集型任务的线程数通常接近 CPU 核心数；I/O 密集型任务可以适当增加，实际数量应结合等待时间和压力测试确定。核心是在并行度和管理开销之间取得平衡。

### 8\. 进程切换和线程切换有什么区别？

两者都需要保存当前执行单元的 CPU 上下文，并恢复下一个执行单元的上下文。区别在于：如果切换到另一个进程，通常还要切换虚拟地址空间及相关内存管理状态；同一进程内的线程共享地址空间和大部分资源，一般不需要完成这些工作。

因此，同一进程内的线程切换通常开销更小。跨进程切换可能使 TLB 和 CPU 缓存的有效内容减少，但现代处理器的地址空间标识等机制可以保留部分 TLB 项，所以不能简单认为每次进程切换都会清空全部缓存。

如果是不同进程中的线程互相切换，本质上同样涉及进程地址空间切换，其成本会更接近进程切换。

### 9\. 为什么线程切换通常比进程切换快，节省了什么资源？

同一进程内的线程共享虚拟地址空间、页表、文件和其他资源，所以线程切换主要保存和恢复寄存器、程序计数器和栈指针等执行上下文。进程切换除了这些操作，通常还要切换虚拟地址空间和页表，并可能降低 TLB 与 CPU 缓存的命中率，因此开销更大。  

### 10\. 线程切换的详细过程是什么？上下文保存在哪里？

线程切换就是 CPU 暂停当前线程，保存它的执行现场，再恢复另一个线程的执行现场。

以操作系统调度的内核线程为例，典型过程是：

1.  当前线程因时间片耗尽、阻塞、主动让出 CPU 或被更高优先级线程抢占而**进入内核态**。
2.  CPU 和内核保存当前线程的程序计数器、栈指针、通用寄存器、状态寄存器等现场。
3.  调度器更新线程状态，从可运行队列中选择下一个线程。
4.  内核切换到目标线程的内核栈，恢复其寄存器和调度上下文；如果目标线程属于另一个进程，还要切换地址空间相关状态。
5.  **恢复新线程的上下文** 从新线程保存的上下文中恢复寄存器、栈指针和程序计数器，然后退出内核态。新线程会从上次暂停的位置继续运行。
    

-   **线程的内核栈**
    
    发生中断或系统调用进入内核时，CPU 寄存器通常会部分由硬件、部分由内核代码压入该线程的内核栈。
    
-   **线程控制块 TCB**   内核再通过 TCB 记录内核栈位置和线程的管理信息。
    

### 11\. 进程有哪些状态？它们如何切换？

经典五状态模型包括：

-   **新建态**：进程正在创建，尚未进入就绪队列；
-   **就绪态**：已经具备运行条件，正在等待 CPU；
-   **运行态**：正在 CPU 上执行；
-   **阻塞态**：正在等待 I/O、锁或某个事件；
-   **终止态**：执行完成或被终止，等待系统完成清理。

主要切换关系是：

-   **新建 → 就绪**：进程创建完成，被操作系统接纳。
-   **就绪 → 运行**：调度器为进程分配 CPU。
-   **运行 → 就绪**：时间片用完，或者被更高优先级任务抢占。
-   **运行 → 阻塞**：进程等待 I/O、锁、信号或其他事件。
-   **阻塞 → 就绪**：等待的事件完成。注意不是直接变成运行状态，还需要等待调度。
-   **运行 → 终止**：进程正常结束、发生致命错误或被其他进程终止。

### 12\. 进程上下文包括哪些内容？

进程上下文是进程暂停后能够恢复执行所需的状态，通常包括：

-   **CPU 上下文**：程序计数器、栈指针、通用寄存器、状态寄存器，以及浮点或 SIMD 状态；
-   **内存上下文**：页表、虚拟内存区域、代码段、数据段、堆和栈等地址空间信息；
-   **内核管理信息**：进程状态、调度优先级、时间统计、内核栈和信号状态等；
-   **资源与运行环境**：打开的文件和套接字、当前目录、权限凭据等。

> 进程上下文主要包括 CPU 上下文、内存上下文和操作系统管理信息。CPU 上下文包括程序计数器、栈指针和寄存器；内存上下文包括页表、代码段、堆、栈及内存映射；管理信息包括进程状态、调度信息、打开的文件、权限和信号等。其中执行上下文实际是线程级的，而地址空间和大部分资源是进程级的。

## 进程间通信

### 1\. 进程间通信有哪些方式？

常见的进程间通信（IPC）方式包括：

-   **管道**：包括匿名管道和命名管道，适合传输字节流；
-   **消息队列**：以消息为单位发送和接收数据；
-   **共享内存**：多个进程映射同一段物理内存，数据传输开销较小，但需要额外同步；
-   **信号量**：主要用于进程间同步和互斥，也可表达有限的计数信息；
-   **信号**：用于异步通知，只能携带有限信息；
-   **套接字**：既可用于同一主机，也可用于跨主机通信；
-   **内存映射文件**：多个进程通过映射同一文件共享数据。

常见的进程间通信方式包括管道、消息队列、共享内存、信号量、信号、Socket 和内存映射文件。管道适合字节流通信；消息队列按消息传递数据；共享内存速度快，但需要配合同步机制；信号用于事件通知；Socket 最通用，既支持本机通信也支持跨网络通信。

<span style="color: rgb(32, 52, 71)">2\. 管道有哪几种？</span>

管道主要分为两种：

-   **匿名管道**：没有文件名，通常用于具有亲缘关系的进程，例如父子进程。Unix/Linux 中 `pipe()` 创建的普通管道是单向字节流；需要双向通信时通常建立两条管道，或使用支持双向通信的其他 IPC。
-   **命名管道（FIFO）**：在文件系统中有名字，无亲缘关系的进程也可以通过约定路径打开并通信。它仍然按照先进先出的字节流方式工作。

匿名管道没有文件名，通常用于父子进程等具有亲缘关系的进程；命名管道以 FIFO 文件形式存在于文件系统中，无亲缘关系的进程也能通信。两者通常都是半双工字节流，如果需要双向通信，一般使用两条管道。  

### 3\. 信号和信号量有什么区别？

信号和信号量用途不同：**信号用于异步事件通知，信号量用于同步、互斥或资源计数**。

信号是一种异步事件通知机制，用来告诉进程某个事件发生了，例如终止或子进程退出；信号量是一种同步机制，本质是受原子操作保护的计数器，用来协调多个进程或线程访问共享资源。简单来说，信号负责“通知发生了什么”，信号量负责“是否允许继续执行”。  

### 4\. 共享内存是怎么实现的？

共享内存的核心是**让多个进程的不同虚拟地址，通过各自的页表映射到同一组物理内存页**。虽然这些虚拟地址可以不同，但最终指向相同的物理页。因此建立映射后，进程可以直接访问同一份数据，避免在进程之间反复复制大块数据，性能通常较高。

常见实现包括 POSIX 共享内存配合 `mmap()`、System V 共享内存，以及多个进程使用 `mmap()` 共同映射同一个文件。

共享内存只解决数据共享，不保证并发安全。多个进程同时读写时，还需要配合进程共享的互斥锁、信号量或原子操作，并考虑数据布局、内存可见性、对象生命周期，以及进程异常退出后的恢复问题。

## 线程同步

### 1\. 线程间通信有哪些方式？

  

-   使用互斥锁、读写锁或自旋锁保护共享数据；
-   使用条件变量、事件或信号量进行等待与通知；
-   使用线程安全的消息队列，把共享状态转换为消息传递；
-   使用原子变量和无锁数据结构完成简单状态通信；
-   使用 `Future`、`Promise` 等高层抽象传递异步结果。

线程局部存储用于保存线程私有数据，不属于线程间共享通信方式。实际开发中通常优先选择线程池、并发队列等成熟抽象，减少手工管理共享状态。

同一进程内的线程共享地址空间、堆和全局变量，因此线程间通信本质上通常是：**通过共享数据交换信息，再通过同步机制保证安全和顺序。**

常见方式有：

1.  **共享变量**
    
    线程可以直接读写全局变量、堆对象等共享数据。速度快，但可能产生数据竞争。
    
2.  **互斥锁（Mutex）**
    
    保证同一时刻只有一个线程进入临界区，适合保护共享数据。
    
3.  **读写锁（Read-Write Lock）**
    
    允许多个线程同时读取，但写操作需要独占，适合读多写少的场景。
    
4.  **条件变量（Condition Variable）**
    
    让线程等待某个条件成立，通常必须配合互斥锁使用。例如生产者—消费者模型。
    
5.  **信号量（Semaphore）**
    
    通过计数控制可同时访问某项资源的线程数量，也可用于线程间的执行顺序协调。
    
6.  **原子变量与原子操作**
    
    对简单共享状态进行不可分割的读写或修改，开销通常比锁小，但需要注意内存顺序问题。
    
7.  **消息队列或线程安全队列**
    
    线程通过发送和接收消息通信，可以减少直接共享可变状态，使程序更容易维护。
    
8.  **事件、屏障和倒计时器**
    
    -   事件：通知其他线程某件事已经发生
    -   屏障：多个线程都执行到某一点后再继续
    -   倒计时器：等待若干任务全部完成
9.  **线程局部存储（TLS）**
    
    为每个线程保存独立数据，主要用于减少共享和竞争。严格来说，它不是线程间传递信息的方式。
    

### 面试回答

> 同一进程中的线程共享地址空间，因此可以通过全局变量或堆对象直接交换数据。为了防止数据竞争和保证执行顺序，通常配合互斥锁、读写锁、条件变量、信号量和原子操作。也可以使用线程安全队列进行消息传递，减少对共享可变数据的直接访问。需要注意，共享变量负责传递数据，而锁、条件变量等主要负责同步。

### 2\. 除了互斥锁，还有哪些锁？分别适用于什么场景？

常见锁及适用场景有：

-   **读写锁**：允许多个读者同时访问，写者独占，适合读多写少且临界区不能太短的场景；否则维护读写状态的成本可能抵消收益。
-   **自旋锁**：获取失败后不睡眠，而是循环等待，适合临界区很短、竞争较少，并且线程不适合睡眠的场景；等待时间长会浪费 CPU。
-   **可重入锁**：同一线程可以重复获取，适合存在递归调用或嵌套调用的场景，但必须按获取次数正确释放。
-   **乐观锁**：读取时不独占资源，更新时通过版本号或 CAS 检查冲突，适合冲突概率较低的场景；冲突频繁时重试成本较高。
-   **悲观锁**：访问前先加锁，适合冲突概率高、发生冲突后的回滚成本较高的场景。
-   **公平锁与非公平锁**：公平锁按等待顺序获取，可降低饥饿风险但调度开销通常更大；非公平锁允许插队，通常吞吐量更高，但等待时间可能不均衡。

信号量和条件变量也是常用同步原语，但严格来说不一定属于“锁”。选择时应结合读写比例、临界区长度、竞争程度、公平性和是否允许线程阻塞判断。

## 进程调度

### 1\. 常见的进程调度算法有哪些？

常见调度算法包括：

-   **先来先服务（FCFS）**：按到达顺序执行，实现简单，但短任务可能被长任务拖延；
-   **短作业优先（SJF）**：优先执行预计运行时间短的任务，平均等待时间较低，但难以准确预测运行时间，长任务可能饥饿；
-   **最短剩余时间优先（SRTF）**：SJF 的抢占式版本，新到达的更短任务可以抢占当前任务；
-   **优先级调度**：高优先级任务先运行，可抢占或不可抢占，但低优先级任务可能饥饿，可通过优先级老化缓解；
-   **时间片轮转（RR）**：每个就绪进程轮流运行一个时间片，响应较公平；时间片太小会增加切换开销，太大则接近 FCFS；
-   **多级队列调度**：按任务类型或优先级划分多个固定队列，各队列采用不同策略；
-   **多级反馈队列（MLFQ）**：允许任务在不同优先级队列间移动，兼顾交互任务响应速度和长任务吞吐量。

实时系统还会使用最早截止时间优先（EDF）、速率单调调度（RM）等算法。评价调度算法不能只看吞吐量，还要结合响应时间、周转时间、公平性、截止期限和上下文切换成本。
