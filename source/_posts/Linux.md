## 进程查看

### 1\. `ps` 命令里都有哪些选项，`ps` 会展示哪些内容？

`ps` 用于查看**执行命令这一时刻的进程快照**。

不带选项执行 `ps` 时，通常只显示与当前终端、当前用户相关的进程，常见字段包括：

-   `PID`：进程 ID；
-   `TTY`：进程关联的控制终端；
-   `TIME`：进程累计占用的 CPU 时间，不是启动后经过的时间；
-   `CMD`：命令名。

常用的进程选择选项有：

-   `-e` 或 `-A`：显示所有进程；
-   `-a`：显示有终端的其他用户进程，但通常不包含会话首进程；
-   `x`：包含没有控制终端的进程；
-   `-p PID`：只查看指定 PID；
-   `-u USER` 或 `--user USER`：查看指定有效用户的进程；
-   `--ppid PID`：查看指定父进程的子进程；
-   `-C NAME`：按可执行文件名筛选进程。

常用的输出格式选项有：

-   `-f`：使用完整格式，增加 `UID`、`PPID`、启动时间等字段；
-   `f` 或 `--forest`：用树形结构展示进程父子关系；
-   `-l`：使用长格式，显示状态、优先级、内存地址等更多信息；
-   `u`：使用面向用户的格式，常见字段包括 `%CPU`、`%MEM`、`VSZ`、`RSS`、`STAT` 和 `START`；
-   `-o 字段列表`：自定义输出列，例如 `ps -eo pid,ppid,user,stat,%cpu,%mem,cmd`；
-   `--sort=字段`：按指定字段排序，例如 `ps -eo pid,cmd,%cpu --sort=-%cpu` 按 CPU 使用率降序显示。

实际排查中常见的组合是：

```bash
ps aux
ps -ef
ps -eo pid,ppid,user,stat,%cpu,%mem,etime,cmd --sort=-%cpu
```

其中 `ps aux` 常用于观察资源占用，`ps -ef` 更侧重进程的用户、父子关系和完整命令。详细格式中还可能看到：`PPID` 表示父进程 ID，`STAT` 表示进程状态，`VSZ` 表示虚拟内存大小，`RSS` 表示驻留物理内存大小，`ELAPSED` 或 `ETIME` 表示进程已经运行的时间，`COMMAND` 或 `CMD` 表示启动命令及参数。

### 2\. `top` 命令会展示什么？每一项数据分别表示什么？

`top` 用于**动态观察系统负载、CPU、内存以及各进程的资源占用**，输出主要分为系统汇总区和进程列表区。

系统汇总区包含：

1.  **运行时间与负载**：显示当前时间、系统运行时长、登录会话数，以及最近 1、5、15 分钟的 `load average`。平均负载主要统计可运行任务和不可中断睡眠任务的数量，不是 CPU 使用率。
2.  **任务状态**：显示 `total`、`running`、`sleeping`、`stopped` 和 `zombie` 等任务数量。
3.  **CPU 使用情况**：`us` 是用户态时间，`sy` 是内核态时间，`id` 是空闲时间，`wa` 是 I/O 等待时间，`hi`、`si` 分别是硬中断和软中断时间，`st` 是虚拟机被宿主机占用的时间。
4.  **内存与 Swap**：显示 `total`、`free`、`used`、`buff/cache` 和 `avail Mem`。Linux 会利用空闲内存做缓存，因此判断内存余量时通常更应关注 `avail Mem`。

进程列表常见字段包括：`PID`、`USER`、调度优先级 `PR`、nice 值 `NI`、虚拟内存 `VIRT`、驻留内存 `RES`、共享内存 `SHR`、进程状态 `S`、`%CPU`、`%MEM`、累计 CPU 时间 `TIME+` 和命令名 `COMMAND`。

实际排查时，我会先从汇总区判断压力大致来自 CPU、内存还是 I/O，再按 `P` 或 `M` 对进程的 CPU、内存占用排序。`top` 展示的是周期性采样结果，具体结论还要结合连续趋势和其他监控指标判断。

### 3\. 已知一个进程名，如何杀掉这个进程？

我会先精确确认目标进程，再发送 `SIGTERM` 让它正常清理并退出；只有进程无响应时，才使用 `SIGKILL` 强制终止：

```bash
pgrep -a -x nginx
pkill -x nginx

# 确认仍无法退出时再强制终止
pkill -KILL -x nginx
```

`-x` 表示完整匹配进程名，可以降低误杀名称相似进程的风险。`pkill` 会处理所有符合条件的进程；如果只想终止其中一个，应该先确认 PID，再执行 `kill PID`。`SIGKILL` 不能被进程捕获，可能使数据和资源来不及清理，因此不能一开始就使用 `-9`。

### 4\. Linux 如何查看进程状态？

可以使用 `ps` 查看目标进程的状态和上下文，需要持续观察时再使用 `top`：

```bash
ps -o pid,ppid,user,stat,%cpu,%mem,etime,wchan:24,cmd -p PID
top -p PID
```

`STAT` 的首字符表示主要状态：`R` 表示运行或等待 CPU，`S` 表示可中断睡眠，`D` 表示不可中断睡眠，`T` 表示停止，`Z` 表示僵尸。`WCHAN` 可以辅助观察睡眠中的进程正在内核哪个位置等待。

还可以查看 `/proc/PID/status` 获取状态、线程数、内存和信号等详细信息。进程状态是瞬时结果，分析卡顿时应连续观察，并结合 CPU、I/O、锁和系统调用判断。

### 5\. Linux 如何查看线程状态？

Linux 内核把线程作为可调度任务管理，可以使用 `ps`、`top` 或 `/proc` 查看某个进程中的线程：

```bash
ps -T -p PID -o pid,tid,stat,pcpu,comm,wchan:24
top -H -p PID
ls /proc/PID/task
```

-   `ps -T -p PID`：列出指定进程的所有线程，`PID` 是线程组 ID，`TID` 是线程 ID；
-   `top -H -p PID`：动态观察该进程中各线程的 CPU、内存和状态；
-   `/proc/PID/task/TID/status`：查看某个线程的详细状态；

[![使用 ps 和 top 查看 Linux 线程状态](/img/linux-thread-status.png)](/img/linux-thread-status.png "使用 ps 和 top 查看 Linux 线程状态")

图片中的 `top -H` 会显示全系统线程，`ps -eT` 会显示所有进程的线程；已知目标 PID 时，使用带 `-p PID` 的写法更精确。线程状态码与进程类似，例如 `R`、`S`、`D`、`T`。如果要继续分析线程阻塞原因，还需要根据语言和场景配合调用栈或系统调用工具。

## 系统资源监控

### 1\. 如何通过 `top` 查看 CPU 核心数？

在 Linux 的 `top` 界面中按数字键 `1`，可以在 CPU 汇总视图和逐个逻辑 CPU 的视图之间切换。展开后有多少行类似 `%Cpu0`、`%Cpu1` 的数据，就表示系统当前可见多少个**逻辑 CPU**。

不过逻辑 CPU 数不一定等于物理核心数。超线程开启时，一个物理核心可能对应多个逻辑 CPU；虚拟机和容器中看到的也可能只是分配或允许使用的部分 CPU。

### 2\. `top` 和 `free` 都可以查看内存，它们有什么区别？

两者都能查看系统整体内存，但定位角度不同：**`free` 适合快速查看内存汇总，`top` 适合持续观察内存变化并定位到具体进程。**

-   `free -h` 一次性展示物理内存和 Swap 的 `total`、`used`、`free`、`buff/cache`、`available` 等汇总数据，输出简洁，也方便脚本处理；使用 `free -s 1` 也可以定时刷新。
-   `top` 默认动态刷新，除了系统内存和 Swap 汇总，还能展示每个进程的 `VIRT`、`RES`、`SHR` 和 `%MEM`。

### 3\. 假如 CPU 跑到 100%，排查和解决思路是什么？

CPU 达到 100% 时，我先用 `top` 判断是用户态、内核态还是 I/O 问题，再找到占用最高的进程。然后用 `top -H -p PID` 定位具体线程，结合线程栈、日志和监控分析是否存在死循环、频繁 GC、慢查询或流量突增。线上优先通过限流、扩容或回滚止损，并在重启前保存现场，尽量不用 `kill -9`。恢复后再修复根因并补充监控。

### 4\. Linux 服务器如何查看负载情况？通过哪些指标判断？

我会先用 `uptime` 和 `top` 看 Load Average，并结合 CPU 核数判断是否有任务排队；再看 CPU 的 `us、sy、wa、id`，判断是计算压力还是 I/O 等待。然后用 `free -h` 看可用内存和 Swap，用 `iostat -x` 看磁盘延迟与利用率，最后结合网络连接、进程占用、接口延迟和错误率综合判断，不能只看某一个指标。

可以通过 `uptime`、`top` 或 `/proc/loadavg` 查看最近 1、5、15 分钟的平均负载：

```bash
uptime
cat /proc/loadavg
```

Linux 的 `load average` 主要统计可运行任务和处于不可中断睡眠状态任务的平均数量，所以它不等于 CPU 使用率。通常先把负载与系统可用的逻辑 CPU 数比较：例如 8 个逻辑 CPU 上，长期负载接近 8 表示任务需求接近 CPU 并行处理能力，明显高于 8 说明任务在排队或有较多不可中断等待。但这只是经验判断，容器 CPU 配额、任务类型和持续时间都会影响结论。

<span style="color: rgb(32, 52, 71)">5\. 怎么判断服务器内存是否够用？如何判断性能瓶颈是不是内存？</span>

判断内存是否够用，不能只看 `free`，而应看**可用内存是否长期偏低，以及是否发生持续回收、换页、直接回收停顿或 OOM**。我会先观察：

```bash
free -h
vmstat 1
cat /proc/pressure/memory
```

重点指标包括：

-   `MemAvailable` 或 `available`：内核估算在不发生明显交换的情况下还能提供给新程序的内存；
-   `vmstat` 的 `si`、`so`：每秒从 Swap 换入和换出的数据量，持续非零通常表示存在内存压力；
-   `vmstat` 的 `r`、`b`、`wa`：辅助判断任务是否因回收或换页受到影响；
-   `/proc/pressure/memory` 的 `some` 和 `full`：反映任务因内存压力而停顿的程度；
-   `dmesg` 或内核日志中的 OOM、direct reclaim 等信息；
-   应用延迟、吞吐量、主缺页和进程 RSS 的变化趋势。

然后用 `top`、`ps --sort=-rss`、`smem` 或应用监控定位主要内存消费者。只有在 `available` 长期很低，同时换页、内存压力或回收停顿与业务延迟同步上升，并且排除 CPU、磁盘和网络因素后，才能较有把握地判断瓶颈在内存。容器环境还要查看 cgroup 的内存上限和事件，因为宿主机有空闲内存也不代表容器没有达到限制。

### 6\. 如何判断内存是不是满了？通过什么指标计算内存使用率？

-   如果 `free` 和 `available` 都非常低，而 `used` 很高，内存基本上是满的。
-   Swap 使用频繁且使用率较高，那么内存基本上是满的。
-   如果 `dmesg` 日志出现 OOM 相关信息，说明内存不足导致了一些进程被杀掉。
-   `ps` 或 `top` 显示大部分内存被少数几个进程占用，那么内存基本上是满的。

### 7\. 怎么判断操作系统是否正在进行内存交换？如何统计交换频率？

最直接的方法是用 `vmstat` 连续观察 `si` 和 `so`：

```bash
vmstat 1
```

-   `si`：每秒从 Swap 换入内存的数据量；
-   `so`：每秒从内存换出到 Swap 的数据量。

首行通常是系统启动以来的平均值，判断当前是否正在交换时应重点看后续按间隔刷新的行。如果安装了 `sysstat`，还可以使用：

```bash
sar -W 1 10
```

其中 `pswpin/s` 和 `pswpout/s` 分别表示每秒换入、换出的 Swap 页数。累计值可以从 `/proc/vmstat` 的 `pswpin`、`pswpout` 获取，两次采样做差再除以时间间隔，就能得到这一时段的换页频率。

需要区分 **Swap 已使用** 和 **正在频繁交换**：`free` 显示 Swap 中已有数据，不代表系统此刻仍在换页，因为冷数据可能长期留在 Swap。只有 `si`、`so` 或对应计数器持续增长，并伴随 `available` 偏低、主缺页、内存 PSI 或延迟上升时，才说明交换正在造成明显压力。此外，`vmstat` 的 `bi`、`bo` 是块设备 I/O，不等同于 Swap 换入换出。

## 网络排查

### 1\. 如何查看网络连接情况？

我通常使用 `ss` 查看 Socket 和 TCP 连接：

```bash
ss -tunap
ss -s
```

`-t` 表示 TCP，`-u` 表示 UDP，`-n` 表示直接显示数字地址和端口，`-a` 表示包含监听与非监听 Socket，`-p` 表示显示关联进程，`ss -s` 用于查看汇总信息。输出中的 `Local Address:Port` 是本地地址和端口，`Peer Address:Port` 是对端地址和端口，`State` 会显示 `LISTEN`、`ESTAB`、`TIME-WAIT` 等 TCP 状态。

常见的定向查询包括：

```bash
ss -lnt                 # 查看正在监听的 TCP 端口
ss -ant state established
ss -ant state time-wait
```

普通用户可能无法看到其他用户进程的详细信息。如果需要查看持续的网络流量、路由或网卡统计，还应分别使用 `sar`、`ip -s link`、`ip route` 或抓包工具；`ss` 主要展示 Socket 状态，而不是完整的网络流量。

### 2\. 怎么查看哪个端口被哪个进程占用？

可以使用 `ss` 按端口过滤，并显示关联的进程：

```bash
sudo ss -lntp 'sport = :8080'
```

其中 `-l` 只看监听 Socket，`-n` 不解析服务名，`-t` 只看 TCP，`-p` 显示进程信息。如果需要检查 UDP，可以使用：

```bash
sudo ss -lunp 'sport = :8080'
```

也可以使用 `lsof`：

```bash
sudo lsof -nP -iTCP:8080 -sTCP:LISTEN
sudo lsof -nP -iUDP:8080
```

输出中的 `PID` 和 `COMMAND` 就是占用端口的进程。使用 `sudo` 是因为普通用户通常看不到所有进程的关联信息。查询时还要区分 TCP 与 UDP、监听端口与已建立连接，以及 IPv4 与 IPv6，不能只根据端口数字认定是同一个 Socket。

### 3\. 判断端口通不通可以用什么命令？

测试 TCP 端口时，我通常使用 `nc`：

```bash
nc -vz -w 3 192.0.2.10 8080
```

`-v` 输出详细结果，`-z` 只探测端口而不发送应用数据，`-w 3` 设置超时。如果目标提供 HTTP 服务，还应进一步使用：

```bash
curl -v --connect-timeout 3 http://192.0.2.10:8080/
```

`nc` 成功只能说明 TCP 连接能够建立，不代表上层协议和业务一定正常；`curl` 可以继续验证 HTTP 状态、TLS 和响应内容。`telnet 主机 端口` 也能测试 TCP 建连，但功能较弱。`ping` 使用 ICMP，只能辅助判断主机可达性，不能判断某个 TCP 或 UDP 端口是否开放。

UDP 没有 TCP 那样的握手，可以用 `nc -vzu` 做初步探测，但没有响应不一定代表端口不可达，最好使用对应的应用协议请求或抓包确认。

## 文件权限

### 1\. 修改文件权限用什么命令？

Linux 使用 `chmod` 修改文件或目录的权限，既可以使用符号形式，也可以使用八进制形式：

```bash
chmod u+x script.sh       # 给所有者增加执行权限
chmod g-w file.txt        # 移除所属组的写权限
chmod 640 file.txt        # 所有者读写、所属组只读、其他用户无权限
chmod 755 script.sh       # 所有者可读写执行，其他用户可读和执行
```

`u`、`g`、`o` 分别表示所有者、所属组和其他用户；`r`、`w`、`x` 分别对应读、写、执行，八进制值分别是 `4`、`2`、`1`。目录上的 `x` 表示可以进入和访问目录项，含义与普通文件的执行权限不同。

<span style="color: rgb(32, 52, 71)">文本处理</span>

### 1\. 如何用 Shell 命令替换文件中的字符串？

一般使用 `sed` 的替换命令。

```bash
sed 's/old/new/g' file.txt
sed -i.bak 's/old/new/g' file.txt
```

`s` 表示替换，`g` 表示替换每一行中的所有匹配；没有 `g` 时只替换每行第一次匹配。`-i.bak` 会原地修改文件，并把原文件保存为 `file.txt.bak`。

<span style="color: rgb(32, 52, 71)">2\.</span> `sed` <span style="color: rgb(32, 52, 71)">和</span> `awk` <span style="color: rgb(32, 52, 71)">有什么区别？</span>

核心区别是：**`sed` 更适合按行进行匹配和文本替换，`awk` 更适合按字段解析、计算和生成结构化输出。**

-   `sed` 是流编辑器，擅长删除、替换、插入和选取文本，例如批量修改配置文件；
-   `awk` 会把每行拆成字段，支持变量、条件、循环、数组和算术运算，适合处理日志、表格和统计数据；
-   两者都按流处理文本，不需要把整个文件一次性加载到内存，但具体内存使用还取决于脚本逻辑。

例如替换字符串更适合用 `sed`：

```bash
sed 's/error/ERROR/g' app.log
```

统计第 2 列的数值更适合用 `awk`：

```bash
awk '{sum += $2} END {print sum}' data.txt
```

实际选择取决于任务：简单替换优先 `sed`，涉及字段、条件和统计时优先 `awk`。

### 3\. 如何查找日志中某个字符串出现的次数？

如果要统计的是**包含该字符串的行数**，可以使用固定字符串匹配：

```bash
grep -F -c 'ERROR' app.log
```

如果一行可能出现多次，需要统计字符串的**总出现次数**，GNU `grep` 可以逐个输出匹配项后计数：

```bash
grep -oF 'ERROR' app.log | wc -l
```

`-F` 表示按普通字符串而不是正则表达式匹配，可以避免 `.`、`*` 等字符被解释为正则元字符。以上总次数统计的是不重叠匹配；需要忽略大小写时可以增加 `-i`。如果日志正在写入、经过轮转或包含压缩文件，单次结果只代表实际读取到的文件内容，不能直接当作稳定的业务统计值。

### 4\. 如何查看日志中匹配行的长度？

可以先用 `grep` 找出匹配行，再由 `awk` 输出每行的字符数和内容：

```bash
grep -F 'ERROR' app.log | awk '{print length($0), $0}'
```

如果只关心匹配行中的最大长度，可以使用：

```bash
grep -F 'ERROR' app.log | awk 'length($0) > max {max = length($0)} END {print max + 0}'
```

这里的 `length($0)` 按当前 `awk` 实现和区域设置计算字符或字节；对于 UTF-8 中文，多字节字符的口径可能因实现和环境而不同。如果问题中的“长度”实际是指匹配行的数量，应使用 `grep -F -c 'ERROR' app.log`，需要先明确统计的是行数、出现次数还是每行字符数。

### 5\. 如何查出日志中请求耗时最高的 10 条记录？

如果日志以空白字符分隔，并且第三列是统一单位的纯数字耗时，可以按第三列做数值降序排序，再取前 10 行：

```bash
sort -k3,3nr access.log | head -n 10
```

其中 `-k3,3` 表示只以第三列作为排序键，`n` 表示按数值排序，`r` 表示降序。如果第一行是表头，可以先跳过表头：

```bash
tail -n +2 access.log | sort -k3,3nr | head -n 10
```

这条命令成立的前提是字段确实以空白分隔，第三列格式一致。例如有的记录使用毫秒、有的使用秒，或者耗时包含需要特殊解析的单位时，应先用 `awk` 统一成同一数值口径后再排序。文件很大时，`sort` 可能使用较多内存和临时磁盘；如果只需要前 10 条，可以用 `awk` 维护固定大小的 Top 10，以空间换取更复杂的脚本。
