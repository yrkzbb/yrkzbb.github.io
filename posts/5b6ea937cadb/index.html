网络攻击

网络与基础设施攻击

1. 什么是 DDoS 攻击？怎么防范？

DDoS 的全称是 Distributed Denial of Service，即分布式拒绝服务攻击。攻击者控制大量主机或利用反射放大节点，同时向目标发送流量或请求，耗尽带宽、连接表、CPU、内存等资源，使正常用户无法访问。

常见攻击大致分为三类：

  • 流量型攻击：用大流量占满出口带宽，例如 UDP Flood、DNS/NTP 反射放大。
  • 协议型攻击：消耗网络设备或协议栈状态，例如 SYN Flood、连接耗尽。
  • 应用层攻击：发送看似合法但成本很高的 HTTP 请求，例如集中访问动态接口、搜索或登录接口。

DDoS 很难只靠单台服务器解决，一般要分层防护：在网络入口使用云清洗、高防 IP、CDN 或 Anycast 吸收和清洗流量；在网络与传输层使用防火墙、限速、连接数限制和 SYN Cookie；在应用层使用 WAF、鉴权、验证码、请求频率限制和缓存；同时做好监控告警、容量冗余和应急切换。

DDoS 的本质是利用分布式流量耗尽目标资源，防护核心是入口清洗、分层限流、弹性扩容和快速应急。

2. 了解 DNS 劫持吗？

了解。DNS 劫持就是 DNS 解析结果被篡改，把用户要访问的域名指向错误或恶意 IP，常见表现是广告跳转、钓鱼网站或流量窃取。劫持可能发生在本机、路由器、DNS 服务器或传输链路上。防护上可以使用可信 DNS、DoH 或 DoT 加密查询，使用 DNSSEC 校验解析结果，同时通过 HTTPS 证书校验避免访问到伪造服务器。

DNS 劫持篡改的是域名解析，DNSSEC、加密 DNS 和 HTTPS 可以从不同环节进行防护。

Web 应用安全

1. SQL 注入问题是什么？

SQL 注入是因为程序把用户输入直接拼接进 SQL 语句，导致输入内容被数据库当成 SQL 代码执行。攻击者可能借此绕过登录、读取或修改数据，严重时甚至删除数据或获取更高权限。
防范的核心是使用参数化查询或预编译语句，让用户输入只能作为数据，不能改变 SQL 结构。同时还要限制数据库账号权限、校验输入，并避免把详细数据库错误直接返回给用户。

例如，不安全写法：

如果直接拼接恶意输入，查询逻辑可能被改变。

一句话总结：

SQL 注入的本质是数据被当成了代码；最核心的防护是参数化查询，而不是只靠过滤关键字。

2. CSRF 攻击是什么？

CSRF 的全称是 Cross-Site Request Forgery，即跨站请求伪造。攻击者诱导已经登录目标网站的用户访问恶意页面，由浏览器自动携带目标站点的 Cookie，向目标网站发起用户并不知情的状态变更请求。

CSRF 是跨站请求伪造。攻击者诱导一个已经登录目标网站的用户访问恶意页面，由这个页面向目标网站发送请求。浏览器会自动携带用户的 Cookie，服务器可能误以为请求是用户本人发出的，从而执行转账、修改密码等操作。

比如用户已登录银行网站，又打开恶意网页；恶意网页偷偷发起转账请求。如果银行只根据 Cookie 判断身份，就可能执行操作。

防护方式主要有：

使用 CSRF Token 验证请求来源；将 Cookie 设置为 SameSite=Lax 或 Strict；校验 Origin、Referer；敏感操作要求二次认证，并避免使用 GET 执行修改操作。

需要注意：

HttpOnly 主要防止 JavaScript 读取 Cookie，不能单独防御 CSRF，因为浏览器发送请求时仍会自动携带 Cookie。

一句话总结：

CSRF 是攻击者借用用户已登录的身份，诱导浏览器发送非用户本意的请求；核心防护是 CSRF Token 和 SameSite Cookie。

3. XSS 攻击是什么？

XSS 的全称是 Cross-Site Scripting，即跨站脚本攻击。攻击者让不可信内容以脚本或可执行 HTML 的形式进入受信任页面，使其在其他用户的浏览器中、以该网站的身份执行。

常见类型包括：

  • 存储型 XSS：恶意内容被保存到数据库，之后展示给其他用户时执行，例如评论、个人资料中的脚本。
  • 反射型 XSS：恶意输入来自当前请求，服务端未经安全处理就反射到响应页面中。
  • DOM 型 XSS：漏洞主要发生在前端，JavaScript 把 URL、消息等不可信数据写入 innerHTML 等危险位置。

主要防护方式：

根据 HTML、属性、JavaScript、URL 等不同输出位置进行转义；尽量使用 textContent，避免把不可信内容传给 innerHTML、eval 等危险接口；必要时进行 HTML 白名单过滤，并使用 CSP 限制脚本执行。Cookie 设置 HttpOnly 可以降低会话信息被盗的风险，但不能从根本上阻止 XSS。

一句话总结：

XSS 的本质，是不可信的数据被浏览器当成了脚本执行；核心防护是按输出上下文编码，并避免危险的 DOM 接口。
