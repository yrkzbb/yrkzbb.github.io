    网络攻击

    网络与基础设施攻击

    1. 什么是 DDoS 攻击？怎么防范？

    DDoS 的全称是 Distributed Denial of Service，即分布式拒绝服务攻击。攻击者控制大量主机或利用反射放大节点，同时向目标发送流量或请求，耗尽带宽、连接表、CPU、内存等资源，使正常用户无法访问。

    常见攻击大致分为三类：

    • 流量型攻击：用大流量占满出口带宽，例如 UDP Flood、DNS/NTP 反射放大。
    • 协议型攻击：消耗网络设备或协议栈状态，例如 SYN Flood、连接耗尽。
    • 应用层攻击：发送看似合法但成本很高的 HTTP 请求，例如集中访问动态接口、搜索或登录接口。

    DDoS 很难只靠应用服务器防住，尤其当入口带宽已经被打满时，流量必须在运营商、云清洗中心或 CDN/WAF 等上游节点被过滤。常见防护包括：

    1. 使用 CDN、Anycast、高防 IP 或云端流量清洗，分散和过滤攻击流量。
    2. 在防火墙、负载均衡和网关进行限速、连接数限制、异常特征过滤，并启用 SYN Cookies 等协议栈保护。
    3. 对应用接口做限流、验证码、缓存、熔断和降级，避免少量高成本请求拖垮后端。
    4. 做容量冗余、自动扩缩容和多地域部署，但扩容只能提高承受能力，不能代替流量清洗，也要防止成本失控。
    5. 建立基线监控和应急预案，关注带宽、包速率、连接状态、状态码、来源分布等指标，并保留日志用于溯源和调整规则。

    防护方案要根据攻击发生在网络层、传输层还是应用层选择，单纯封禁源 IP 往往效果有限，因为攻击源可能分散或伪造。

    2. 了解 DNS 劫持吗？

    DNS 劫持是指攻击者或中间网络改变域名解析过程，使用户得到错误的 IP 地址，进而被引导到仿冒网站、广告页面或不可用节点。它是一个统称，可能发生在不同位置。

    常见方式包括篡改本机 hosts 或 DNS 设置、控制路由器、污染递归解析器缓存、运营商或恶意 DNS 返回错误结果，以及盗取域名注册商或 DNS 管理账号后修改权威记录。排查时可以比较本机、可信公共解析器和权威 DNS 的结果，检查 TTL、DNS 配置、路由器和域名控制台，并结合抓包确认响应来源。

    防护措施包括：

    • 使用可信递归 DNS，并通过 DoT、DoH 或 DoQ 加密客户端到解析器的查询，降低这段链路被窃听和篡改的风险；但解析器本身仍需可信。
    • 部署并验证 DNSSEC，利用数字签名验证 DNS 数据来源和完整性；DNSSEC 不负责加密查询，也不是所有域名和客户端链路都完整支持。
    • 保护域名注册商、云 DNS 和路由器账号，启用多因素认证、最小权限、变更审计和注册锁。
    • 网站全程使用 HTTPS，并正确校验证书。DNS 被劫持后，攻击者通常无法为目标域名提供受信任证书，但用户忽略证书警告或终端被安装恶意根证书时仍有风险。
    • 对关键解析记录和证书透明度日志进行监控，发现异常变更及时回滚和处置。

    2. CSRF 攻击是什么？

    CSRF 的全称是 Cross-Site Request Forgery，即跨站请求伪造。攻击者诱导已经登录目标网站的用户访问恶意页面，由浏览器自动携带目标站点的 Cookie，向目标网站发起用户并不知情的状态变更请求。

    它成立通常需要三个条件：用户已在目标站点登录；认证凭证会被浏览器自动携带；服务端无法区分请求是否由可信页面主动发起。攻击者通常不能直接读取跨源响应，但仍可能触发转账、改邮箱等操作。

    常见防护包括：

    • 对状态变更请求校验不可预测、与用户会话绑定的 CSRF Token。
    • 给认证 Cookie 设置合适的 SameSite，并配合 Secure、HttpOnly；但要考虑跨站登录、旧客户端和业务兼容场景，不能只依赖这一项。
    • 校验 Origin，必要时辅助校验 Referer，拒绝来源不可信的敏感请求。
    • 不使用 GET 执行状态变更；高风险操作增加密码确认、一次性验证码等二次验证。
    • 前后端分离接口若通过 Authorization 请求头显式携带 Token，传统 CSRF 风险会降低，因为第三方页面不能随意设置该头，但仍必须防范 XSS、CORS 配置错误等问题。

    如果站点存在 XSS，恶意脚本往往能以站点自身身份读取 Token 或发起请求，因此修复 XSS 也是保障 CSRF 防护有效的重要前提。

    3. XSS 攻击是什么？

    XSS 的全称是 Cross-Site Scripting，即跨站脚本攻击。攻击者让不可信内容以脚本或可执行 HTML 的形式进入受信任页面，使其在其他用户的浏览器中、以该网站的身份执行。

    常见类型包括：

    • 存储型 XSS：恶意内容被保存到数据库，之后展示给其他用户时执行，例如评论、个人资料中的脚本。
    • 反射型 XSS：恶意输入来自当前请求，服务端未经安全处理就反射到响应页面中。
    • DOM 型 XSS：漏洞主要发生在前端，JavaScript 把 URL、消息等不可信数据写入 innerHTML 等危险位置。

    防护的核心是按输出上下文进行编码：HTML 文本、HTML 属性、URL、JavaScript 字符串需要不同的处理方式。应优先使用会自动转义的模板和安全 DOM API，例如用 textContent 代替 innerHTML；如果业务必须展示富文本，应使用成熟的白名单清洗库。

    同时应避免 eval、内联脚本等危险能力，部署严格的 CSP 作为纵深防御，并将会话 Cookie 设置为 HttpOnly、Secure 和合适的 SameSite。HttpOnly 可以降低 Cookie 被直接读取的风险，但恶意脚本仍可能代表用户发起请求，所以它不能单独消除 XSS 危害。
