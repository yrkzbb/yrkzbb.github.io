进程查看

1. ps 命令里都有哪些选项，ps 会展示哪些内容？

ps 用于查看执行命令这一时刻的进程快照。

不带选项执行 ps 时，通常只显示与当前终端、当前用户相关的进程，常见字段包括：

  • PID：进程 ID；
  • TTY：进程关联的控制终端；
  • TIME：进程累计占用的 CPU 时间，不是启动后经过的时间；
  • CMD：命令名。

常用的进程选择选项有：

  • -e 或 -A：显示所有进程；
  • -a：显示有终端的其他用户进程，但通常不包含会话首进程；
  • x：包含没有控制终端的进程；
  • -p PID：只查看指定 PID；
  • -u USER 或 --user USER：查看指定有效用户的进程；
  • --ppid PID：查看指定父进程的子进程；
  • -C NAME：按可执行文件名筛选进程。

常用的输出格式选项有：

  • -f：使用完整格式，增加 UID、PPID、启动时间等字段；
  • f 或 --forest：用树形结构展示进程父子关系；
  • -l：使用长格式，显示状态、优先级、内存地址等更多信息；
  • u：使用面向用户的格式，常见字段包括 %CPU、%MEM、VSZ、RSS、STAT 和 START；
  • -o 字段列表：自定义输出列，例如 ps -eo pid,ppid,user,stat,%cpu,%mem,cmd；
  • --sort=字段：按指定字段排序，例如 ps -eo pid,cmd,%cpu --sort=-%cpu 按 CPU 使用率降序显示。

2. top 命令会展示什么？每一项数据分别表示什么？

top 用于动态观察系统负载、CPU、内存以及各进程的资源占用，输出主要分为系统汇总区和进程列表区。

系统汇总区包含：

  1. 运行时间与负载：显示当前时间、系统运行时长、登录会话数，以及最近 1、5、15 分钟的 load average。平均负载主要统计可运行任务和不可中断睡眠任务的数量，不是 CPU 使用率。
  2. 任务状态：显示 total、running、sleeping、stopped 和 zombie 等任务数量。
  3. CPU 使用情况：us 是用户态时间，sy 是内核态时间，id 是空闲时间，wa 是 I/O 等待时间，hi、si 分别是硬中断和软中断时间，st 是虚拟机被宿主机占用的时间。
  4. 内存与 Swap：显示 total、free、used、buff/cache 和 avail Mem。Linux 会利用空闲内存做缓存，因此判断内存余量时通常更应关注 avail Mem。

进程列表常见字段包括：PID、USER、调度优先级 PR、nice 值 NI、虚拟内存 VIRT、驻留内存 RES、共享内存 SHR、进程状态 S、%CPU、%MEM、累计 CPU 时间 TIME+ 和命令名 COMMAND。

实际排查时，我会先从汇总区判断压力大致来自 CPU、内存还是 I/O，再按 P 或 M 对进程的 CPU、内存占用排序。top 展示的是周期性采样结果，具体结论还要结合连续趋势和其他监控指标判断。

STAT 的首字符表示主要状态：R 表示运行或等待 CPU，S 表示可中断睡眠，D 表示不可中断睡眠，T 表示停止，Z 表示僵尸。WCHAN 可以辅助观察睡眠中的进程正在内核哪个位置等待。

5. Linux 如何查看线程状态？

Linux 内核把线程作为可调度任务管理，可以使用 ps、top 或 /proc 查看某个进程中的线程：

  • ps -T -p PID：列出指定进程的所有线程，PID 是线程组 ID，TID 是线程 ID；
  • top -H -p PID：动态观察该进程中各线程的 CPU、内存和状态；
  • /proc/PID/task/TID/status：查看某个线程的详细状态；

图片中的 top -H 会显示全系统线程，ps -eT 会显示所有进程的线程；已知目标 PID 时，使用带 -p PID 的写法更精确。线程状态码与进程类似，例如 R、S、D、T。如果要继续分析线程阻塞原因，还需要根据语言和场景配合调用栈或系统调用工具。

系统资源监控

1. 如何通过 top 查看 CPU 核心数？

在 Linux 的 top 界面中按数字键 1，可以在 CPU 汇总视图和逐个逻辑 CPU 的视图之间切换。展开后有多少行类似 %Cpu0、%Cpu1 的数据，就表示系统当前可见多少个逻辑 CPU。

不过逻辑 CPU 数不一定等于物理核心数。超线程开启时，一个物理核心可能对应多个逻辑 CPU；虚拟机和容器中看到的也可能只是分配或允许使用的部分 CPU。

2. top 和 free 都可以查看内存，它们有什么区别？

两者都能查看系统整体内存，但定位角度不同：free 适合快速查看内存汇总，top 适合持续观察内存变化并定位到具体进程。

  • free -h 一次性展示物理内存和 Swap 的 total、used、free、buff/cache、available 等汇总数据，输出简洁，也方便脚本处理；使用 free -s 1 也可以定时刷新。
  • top 默认动态刷新，除了系统内存和 Swap 汇总，还能展示每个进程的 VIRT、RES、SHR 和 %MEM。

3. 假如 CPU 跑到 100%，排查和解决思路是什么？

CPU 达到 100% 时，我先用 top 判断是用户态、内核态还是 I/O 问题，再找到占用最高的进程。然后用 top -H -p PID 定位具体线程，结合线程栈、日志和监控分析是否存在死循环、频繁 GC、慢查询或流量突增。线上优先通过限流、扩容或回滚止损，并在重启前保存现场，尽量不用 kill -9。恢复后再修复根因并补充监控。

4. Linux 服务器如何查看负载情况？通过哪些指标判断？

我会先用 uptime 和 top 看 Load Average，并结合 CPU 核数判断是否有任务排队；再看 CPU 的 us、sy、wa、id，判断是计算压力还是 I/O 等待。然后用 free -h 看可用内存和 Swap，用 iostat -x 看磁盘延迟与利用率，最后结合网络连接、进程占用、接口延迟和错误率综合判断，不能只看某一个指标。

可以通过 uptime、top 或 /proc/loadavg 查看最近 1、5、15 分钟的平均负载：

Linux 的 load average 主要统计可运行任务和处于不可中断睡眠状态任务的平均数量，所以它不等于 CPU 使用率。通常先把负载与系统可用的逻辑 CPU 数比较：例如 8 个逻辑 CPU 上，长期负载接近 8 表示任务需求接近 CPU 并行处理能力，明显高于 8 说明任务在排队或有较多不可中断等待。但这只是经验判断，容器 CPU 配额、任务类型和持续时间都会影响结论。

5. 怎么判断服务器内存是否够用？如何判断性能瓶颈是不是内存？

判断内存是否够用，不能只看 free，而应看可用内存是否长期偏低，以及是否发生持续回收、换页、直接回收停顿或 OOM。我会先观察：

重点指标包括：

  • MemAvailable 或 available：内核估算在不发生明显交换的情况下还能提供给新程序的内存；
  • vmstat 的 si、so：每秒从 Swap 换入和换出的数据量，持续非零通常表示存在内存压力；
  • vmstat 的 r、b、wa：辅助判断任务是否因回收或换页受到影响；
  • /proc/pressure/memory 的 some 和 full：反映任务因内存压力而停顿的程度；
  • dmesg 或内核日志中的 OOM、direct reclaim 等信息；
  • 应用延迟、吞吐量、主缺页和进程 RSS 的变化趋势。

然后用 top、ps --sort=-rss、smem 或应用监控定位主要内存消费者。只有在 available 长期很低，同时换页、内存压力或回收停顿与业务延迟同步上升，并且排除 CPU、磁盘和网络因素后，才能较有把握地判断瓶颈在内存。容器环境还要查看 cgroup 的内存上限和事件，因为宿主机有空闲内存也不代表容器没有达到限制。

6. 如何判断内存是不是满了？通过什么指标计算内存使用率？

  • 如果 free 和 available 都非常低，而 used 很高，内存基本上是满的。
  • Swap 使用频繁且使用率较高，那么内存基本上是满的。
  • 如果 dmesg 日志出现 OOM 相关信息，说明内存不足导致了一些进程被杀掉。
  • ps 或 top 显示大部分内存被少数几个进程占用，那么内存基本上是满的。

7. 怎么判断操作系统是否正在进行内存交换？如何统计交换频率？

2. sed 和 awk 有什么区别？

核心区别是：sed 更适合按行进行匹配和文本替换，awk 更适合按字段解析、计算和生成结构化输出。

  • sed 是流编辑器，擅长删除、替换、插入和选取文本，例如批量修改配置文件；
  • awk 会把每行拆成字段，支持变量、条件、循环、数组和算术运算，适合处理日志、表格和统计数据；
  • 两者都按流处理文本，不需要把整个文件一次性加载到内存，但具体内存使用还取决于脚本逻辑。
