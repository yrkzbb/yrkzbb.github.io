中断

中断基础

1. 什么是中断？

中断是一种让 CPU 暂时停止当前执行流程，转而处理特定事件，处理完成后再恢复原流程的机制。

例如，网卡收到数据、磁盘完成 I/O、定时器到期时，设备可以通知 CPU 执行相应的中断处理程序。这样 CPU 不必一直轮询设备状态，可以在设备工作期间执行其他任务。

广义上，硬件中断、CPU 执行指令时产生的异常，以及软件主动触发的陷入，都可能使控制权转移到内核。不过严格分类中，外部硬件中断通常是异步的，异常则与当前指令同步发生，二者不能完全等同。

2. 中断的处理流程是怎样的？

以外部硬件中断为例，典型流程如下：

  1. 设备完成操作或发生事件，向中断控制器发出中断请求；
  2. 中断控制器根据屏蔽状态和优先级选择中断，并把中断向量通知 CPU；
  3. CPU 通常在当前指令执行到可中断边界后响应请求，保存返回位置和必要的处理器状态；如果从用户态进入内核态，还会切换特权级和相应的栈；
  4. CPU 根据中断向量找到入口代码，内核入口继续保存需要保护的寄存器上下文；
  5. 中断处理程序确认中断来源，读取或写入设备状态，清除中断条件，并向中断控制器发送处理完成信号；
  6. 对耗时较长的工作，内核通常只在中断上下文中完成紧急部分，再把其余任务推迟到软中断、工作队列等机制中执行；
  7. 处理结束后，内核可能检查是否需要调度其他任务，随后恢复上下文并执行中断返回，从原来的位置或被调度的新任务继续运行。

中断响应期间是否屏蔽同级中断、能否被更高优先级中断嵌套，以及上下文具体保存在哪里，会因 CPU 架构和操作系统实现而不同。

3. 中断的类型有哪些？

常见分类可以从触发来源和是否可屏蔽两个角度理解。

按触发来源划分：

  • 外部硬件中断：由 CPU 外部设备异步触发，例如时钟、网卡、磁盘和键盘中断；
  • 异常：CPU 执行当前指令时同步产生，例如缺页、除零、非法指令和调试断点。异常还可根据能否恢复细分为故障、陷阱和终止等类型；
  • 软件触发的中断或陷入：程序执行专门指令，主动把控制权交给内核。传统系统调用可以使用软件中断实现，现代处理器通常还提供开销更低的专用系统调用指令，因此不能认为系统调用一定通过软件中断完成。

按是否可以屏蔽划分：

  • 可屏蔽中断：可以由 CPU 或中断控制器暂时屏蔽，多数普通设备中断属于这一类；
  • 不可屏蔽中断（NMI）：普通中断屏蔽机制不能禁止，通常用于硬件严重错误、看门狗等必须及时处理的事件。

不同教材和 CPU 架构对“中断”与“异常”的术语范围可能不同，回答时应先说明采用的是广义还是狭义定义。

4. 中断的作用是什么？

中断的核心作用是让 CPU 及时响应异步事件，并避免低效地持续轮询。主要体现在：

  • 处理设备 I/O：设备完成操作后主动通知 CPU，提高 CPU 与外设并行工作的效率；
  • 支持任务调度：周期性时钟中断使操作系统能够更新时间、统计运行时间并实施抢占式调度；
  • 处理异常和保护系统：通过缺页、权限错误、非法指令等异常把控制权交给内核，由内核修复、报告或终止任务；
  • 提供受控的内核入口：软件陷入或专用系统调用指令让用户程序以受控方式请求内核服务；
  • 响应紧急事件：通过高优先级中断或 NMI 处理部分严重硬件故障和看门狗事件。

中断能提高系统响应性，但并非越多越好。过高的中断频率会占用大量 CPU 时间，因此系统还会使用中断合并、轮询与中断混合等方式控制开销。
