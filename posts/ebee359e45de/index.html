    进程管理

    进程与线程

    1. 线程和进程的区别是什么？

    核心区别是：进程是资源分配和隔离的基本单位，线程是 CPU 调度和执行的基本单位。

    • 进程通常拥有独立的虚拟地址空间、文件描述符表和权限信息等资源；同一进程内的线程共享这些资源。
    • 每个线程都有自己的程序计数器、寄存器、栈和线程局部存储，以保存独立的执行状态。
    • 进程之间默认相互隔离，通信需要借助 IPC；线程共享进程内存，通信更直接，但必须处理并发同步问题。
    • 创建和切换进程通常比同一进程内的线程开销大，但具体差距取决于操作系统实现和工作负载。
    • 一个线程发生普通错误，通常会导致其所在进程退出，进而影响该进程内的其他线程；一个普通进程崩溃通常不会直接破坏其他进程。

    2. 进程、线程、协程的区别是什么？

    三者主要区别在于资源隔离、调度主体和切换成本：

    对比项 进程 线程 协程
    资源关系 拥有独立地址空间和系统资源 共享所属进程的大部分资源 通常共享所属线程的资源
    调度者 操作系统内核 操作系统内核 通常由语言运行时或用户态调度器调度
    独立状态 地址空间、进程上下文等 寄存器、栈、线程局部存储等 协程栈、程序位置等
    切换开销 通常较大 通常小于进程 通常最小，可在用户态完成
    隔离性 强 较弱 更弱

    协程适合大量 I/O 密集型任务，但协程本身不等于并行。如果多个协程只运行在一个内核线程上，它们无法同时使用多个 CPU 核心；而且一次阻塞式系统调用还可能阻塞整个线程，除非运行时使用异步 I/O 或把任务调度到其他线程。

    3. 为什么进程崩溃通常不会对其他进程产生很大影响？

    核心原因是操作系统通过虚拟内存和权限机制实现了进程隔离。每个进程通常拥有独立的虚拟地址空间，进程只能访问页表中映射且权限允许的内存。发生越界访问等异常时，CPU 会陷入内核，操作系统一般只终止或通知当前进程，并回收它占用的资源。

    不过这不是绝对的。进程可能通过共享内存、文件、套接字等方式影响其他进程；关键服务崩溃也可能造成业务不可用。如果进程触发了内核或驱动缺陷、耗尽系统资源，影响范围还可能扩展到整个系统。

    4. 进程是分配资源的基本单位，这里的资源指什么？

    这里主要指操作系统为进程建立或管理的资源集合，例如：

    • 独立的虚拟地址空间，包括代码段、数据段、堆、栈和内存映射；
    • 打开的文件、套接字、管道等内核对象及其描述符；
    • 进程身份和权限信息，例如用户 ID、用户组和安全凭据；
    • 信号处理配置、当前工作目录、环境变量等运行环境；
    • CPU 时间、内存等资源的使用统计和限制。

    “基本单位”不代表所有资源都完全独占。例如同一进程的线程共享地址空间和文件描述符，一些内存页、动态库和文件也可以在多个进程之间共享。

    5. 为什么进程之下还要设计线程？

    主要是为了在保留进程资源边界的同时，提供一种更轻量的并发执行方式。

    如果只使用进程，一个应用的多个执行任务需要各自维护地址空间，并通过 IPC 交换数据，创建、通信和切换成本相对较高。线程共享同一进程的内存和文件等资源，可以方便地协作；当一个线程等待 I/O 时，其他线程仍可运行；在多核 CPU 上，多个线程还可以真正并行执行。

    代价是共享状态会带来数据竞争、死锁等问题，而且一个线程的严重错误往往会影响整个进程。

    6. 多线程相比单线程有哪些优势和劣势？

    多线程的主要优势是提升并发能力和响应性：I/O 密集型任务可以在部分线程等待时运行其他任务；CPU 密集型任务在可并行拆分且有多核资源时，也可能缩短总耗时。此外，线程间共享数据比进程间通信更直接。

    它的劣势是程序复杂度和运行开销都会增加，包括线程创建与切换、栈内存占用、锁竞争和缓存一致性开销。共享数据还可能产生竞态条件、死锁、活锁和可见性问题，使测试与排查更困难。

    因此，多线程并不一定比单线程快。任务规模小、难以并行，或者同步竞争严重时，单线程反而可能更简单、更高效。

    7. 多线程是不是越多越好？线程太多会有什么问题？

    不是。合适的线程数取决于任务类型、CPU 核数、阻塞比例、内存限制和外部资源容量。

    线程过多可能导致：

    • 调度和上下文切换增多，CPU 时间消耗在切换而不是业务计算上；
    • 每个线程的栈和管理结构占用内存，严重时可能耗尽内存；
    • 线程争抢锁、CPU 缓存、数据库连接和磁盘等资源，吞吐量反而下降；
    • 缓存失效和缓存一致性开销增加，尾延迟变差；
    • 超过系统线程数、文件描述符或下游服务限制。

    CPU 密集型任务的工作线程数通常接近可用 CPU 核数；I/O 密集型任务可以适当增加，但应通过线程池设置上限，并结合压测结果、CPU 利用率、阻塞时间和下游容量调整，不能只套固定公式。

    8. 进程切换和线程切换有什么区别？

    两者都需要保存当前执行单元的 CPU 上下文，并恢复下一个执行单元的上下文。区别在于：如果切换到另一个进程，通常还要切换虚拟地址空间及相关内存管理状态；同一进程内的线程共享地址空间和大部分资源，一般不需要完成这些工作。

    因此，同一进程内的线程切换通常开销更小。跨进程切换可能使 TLB 和 CPU 缓存的有效内容减少，但现代处理器的地址空间标识等机制可以保留部分 TLB 项，所以不能简单认为每次进程切换都会清空全部缓存。

    如果是不同进程中的线程互相切换，本质上同样涉及进程地址空间切换，其成本会更接近进程切换。

    9. 为什么线程切换通常比进程切换快，节省了什么资源？

    这里主要指同一进程内的线程切换。它通常不需要切换页表和虚拟地址空间，也不需要更换文件描述符等共享资源，因此减少了内存管理相关操作，并更有可能保留有效的 TLB 和 CPU 缓存数据。

    不过，线程切换仍要保存和恢复程序计数器、栈指针、通用寄存器等执行上下文，也会进入内核调度，并可能造成缓存扰动。它是“通常更快”，不是没有成本；若线程间锁竞争严重或工作集差异很大，间接开销仍可能很明显。

    10. 线程切换的详细过程是什么？上下文保存在哪里？

    以操作系统调度的内核线程为例，典型过程是：

    1. 当前线程因时间片耗尽、阻塞、主动让出 CPU 或被更高优先级线程抢占而进入内核。
    2. CPU 和内核保存当前线程的程序计数器、栈指针、通用寄存器、状态寄存器等现场。
    3. 调度器更新线程状态，从可运行队列中选择下一个线程。
    4. 内核切换到目标线程的内核栈，恢复其寄存器和调度上下文；如果目标线程属于另一个进程，还要切换地址空间相关状态。
    5. 从内核返回后，目标线程从上次暂停的位置继续运行。

    上下文通常保存在该线程的内核栈以及内核维护的线程控制结构中，例如 Linux 的 task_struct 及架构相关线程结构。浮点和 SIMD 寄存器等扩展状态也需要保存，具体保存时机和位置取决于操作系统与 CPU 架构。用户态协程切换则通常由运行时把必要寄存器、栈指针等保存到协程对象中，不一定进入内核。

    11. 进程有哪些状态？它们如何切换？

    经典五状态模型包括：

    • 新建态：进程正在创建，尚未进入就绪队列；
    • 就绪态：已经具备运行条件，正在等待 CPU；
    • 运行态：正在 CPU 上执行；
    • 阻塞态：正在等待 I/O、锁或某个事件；
    • 终止态：执行完成或被终止，等待系统完成清理。

    主要切换关系是：新建完成后进入就绪态；调度器选中后由就绪态进入运行态；时间片用完或被抢占时回到就绪态；等待 I/O 或事件时进入阻塞态；等待条件满足后回到就绪态；运行完成或被终止时进入终止态。

    有些教材或操作系统还会细分挂起、僵尸等状态，但它们不属于经典五状态模型中的五种基本状态。

    12. 进程上下文包括哪些内容？

    进程上下文是进程暂停后能够恢复执行所需的状态，通常包括：

    • CPU 上下文：程序计数器、栈指针、通用寄存器、状态寄存器，以及浮点或 SIMD 状态；
    • 内存上下文：页表、虚拟内存区域、代码段、数据段、堆和栈等地址空间信息；
    • 内核管理信息：进程状态、调度优先级、时间统计、内核栈和信号状态等；
    • 资源与运行环境：打开的文件和套接字、当前目录、权限凭据等。

    上下文切换时并不会复制上述全部内容。内核主要切换恢复执行所必需的 CPU、调度和地址空间状态，其余资源通常仍由内核数据结构持有并按需访问。

    进程间通信

    1. 进程间通信有哪些方式？

    常见的进程间通信（IPC）方式包括：

    • 管道：包括匿名管道和命名管道，适合传输字节流；
    • 消息队列：以消息为单位发送和接收数据；
    • 共享内存：多个进程映射同一段物理内存，数据传输开销较小，但需要额外同步；
    • 信号量：主要用于进程间同步和互斥，也可表达有限的计数信息；
    • 信号：用于异步通知，只能携带有限信息；
    • 套接字：既可用于同一主机，也可用于跨主机通信；
    • 内存映射文件：多个进程通过映射同一文件共享数据。

    选择时要结合通信范围、数据量、吞吐与延迟、消息边界、同步需求和实现复杂度。例如大数据量的本机通信可考虑共享内存，而跨主机通信通常使用套接字。

    2. 管道有哪几种？

    管道主要分为两种：

    • 匿名管道：没有文件名，通常用于具有亲缘关系的进程，例如父子进程。Unix/Linux 中 pipe() 创建的普通管道是单向字节流；需要双向通信时通常建立两条管道，或使用支持双向通信的其他 IPC。
    • 命名管道（FIFO）：在文件系统中有名字，无亲缘关系的进程也可以通过约定路径打开并通信。它仍然按照先进先出的字节流方式工作。

    两者传输的数据通常由内核缓冲区暂存，容量有限；写满时写端可能阻塞，读空时读端可能阻塞，具体行为还取决于是否使用非阻塞模式。

    3. 信号和信号量有什么区别？

    信号和信号量用途不同：信号用于异步事件通知，信号量用于同步、互斥或资源计数。

    • 信号由内核通知进程发生了某个事件，例如 SIGINT、SIGTERM；进程可以使用默认行为、忽略部分信号或注册处理函数。传统信号通常不能可靠累计同类事件，能携带的信息也有限。
    • 信号量维护一个计数值。执行等待操作时，计数不足的线程或进程会阻塞；释放操作增加计数并唤醒等待者。计数信号量适合管理固定数量的资源，二值信号量可用于互斥或事件同步。

    因此，二者虽然名称相似，但不能互相等价替代。

    4. 共享内存是怎么实现的？

    共享内存的核心是：操作系统把同一组物理内存页映射到多个进程各自的虚拟地址空间中。这些虚拟地址可以不同，但页表项最终指向相同的物理页，因此一个进程写入后，其他进程可以直接读取，不需要在进程之间反复复制大块数据。

    常见实现包括 POSIX 共享内存配合 mmap()、System V 共享内存，以及多个进程共同 mmap() 同一个文件。

    共享内存只解决数据共享，不自动保证并发安全。多个进程同时读写时，还需要配合进程共享的互斥锁、信号量或原子操作，并设计好数据布局、生命周期和异常退出后的恢复方式。

    线程同步

    1. 线程间通信有哪些方式？

    同一进程的线程天然共享地址空间，因此可以直接通过共享变量和共享对象交换数据，但需要同步机制保证可见性和一致性。常见方式包括：

    • 使用互斥锁、读写锁或自旋锁保护共享数据；
    • 使用条件变量、事件或信号量进行等待与通知；
    • 使用线程安全的消息队列，把共享状态转换为消息传递；
    • 使用原子变量和无锁数据结构完成简单状态通信；
    • 使用 Future、Promise 等高层抽象传递异步结果。

    线程局部存储用于保存线程私有数据，不属于线程间共享通信方式。实际开发中通常优先选择线程池、并发队列等成熟抽象，减少手工管理共享状态。

    2. 除了互斥锁，还有哪些锁？分别适用于什么场景？

    常见锁及适用场景有：

    • 读写锁：允许多个读者同时访问，写者独占，适合读多写少且临界区不能太短的场景；否则维护读写状态的成本可能抵消收益。
    • 自旋锁：获取失败后不睡眠，而是循环等待，适合临界区很短、竞争较少，并且线程不适合睡眠的场景；等待时间长会浪费 CPU。
    • 可重入锁：同一线程可以重复获取，适合存在递归调用或嵌套调用的场景，但必须按获取次数正确释放。
    • 乐观锁：读取时不独占资源，更新时通过版本号或 CAS 检查冲突，适合冲突概率较低的场景；冲突频繁时重试成本较高。
    • 悲观锁：访问前先加锁，适合冲突概率高、发生冲突后的回滚成本较高的场景。
    • 公平锁与非公平锁：公平锁按等待顺序获取，可降低饥饿风险但调度开销通常更大；非公平锁允许插队，通常吞吐量更高，但等待时间可能不均衡。

    信号量和条件变量也是常用同步原语，但严格来说不一定属于“锁”。选择时应结合读写比例、临界区长度、竞争程度、公平性和是否允许线程阻塞判断。

    进程调度

    1. 常见的进程调度算法有哪些？

    常见调度算法包括：

    • 先来先服务（FCFS）：按到达顺序执行，实现简单，但短任务可能被长任务拖延；
    • 短作业优先（SJF）：优先执行预计运行时间短的任务，平均等待时间较低，但难以准确预测运行时间，长任务可能饥饿；
    • 最短剩余时间优先（SRTF）：SJF 的抢占式版本，新到达的更短任务可以抢占当前任务；
    • 优先级调度：高优先级任务先运行，可抢占或不可抢占，但低优先级任务可能饥饿，可通过优先级老化缓解；
    • 时间片轮转（RR）：每个就绪进程轮流运行一个时间片，响应较公平；时间片太小会增加切换开销，太大则接近 FCFS；
    • 多级队列调度：按任务类型或优先级划分多个固定队列，各队列采用不同策略；
    • 多级反馈队列（MLFQ）：允许任务在不同优先级队列间移动，兼顾交互任务响应速度和长任务吞吐量。

    实时系统还会使用最早截止时间优先（EDF）、速率单调调度（RM）等算法。评价调度算法不能只看吞吐量，还要结合响应时间、周转时间、公平性、截止期限和上下文切换成本。
